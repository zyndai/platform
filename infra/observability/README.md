# Monitoring stack (single box)

Metrics, logs and dashboards for everything on the single box: the pm2 apps
(persona-api, persona-web, cards-web, prod and dev), the Docker containers
(memory, mcp, worker, plugins, cards-api, Postgres, Redis) and Caddy.

| Piece | Job | Port (127.0.0.1) |
|---|---|---|
| Prometheus | metrics, 30 days | 9090 |
| Loki | logs, 14 days | 3100 |
| Alloy | ships pm2, Docker and Caddy logs to Loki | 12345 |
| Grafana | dashboards, explore | 3030 |
| node_exporter | the box: RAM, CPU, disk, network | 9100 |
| cAdvisor | per-container RAM and CPU | 9180 |
| blackbox | uptime and TLS of the public URLs | 9115 |
| pm2 exporter | per-process RAM, CPU, restarts (a systemd service, not a container) | 9209 |

Two public URLs, both served by host Caddy (`infra/single-box/Caddyfile`):
**https://monitor.zynd.ai** (Grafana, its own login) and **https://metrics.zynd.ai**
(Prometheus, HTTP basic auth; the credentials and how to change them are in
`docs/MONITORING.md`, "Public URLs"). Loki and everything else listen on loopback only; search
logs through Grafana's Explore. The SSH tunnel is the fallback:

```
ssh -L 3030:127.0.0.1:3030 <box>      # then http://localhost:3030
```

Login is `admin`; the first-run password is in `~/.zynd-obs/.env` on the box
(`GRAFANA_ADMIN_PASSWORD`, generated by `apply.sh`). That variable only seeds the first
start: change the password in Grafana (Profile) and create a named account per person
(Administration -> Users and access), and the `.env` value is then stale.

## Labels

Every metric and log line carries `project` and `env`, so one dropdown filters
both:

- `project`: `cards-api`, `memory-api`, `mcp`, `worker`, `chatgpt-plugin`,
  `claude-plugin`, `postgres`, `redis`, `cards-web`, `persona-api`,
  `persona-web`, `caddy`, `box`, `monitoring`
- `env`: `prod`, `dev`, `shared` (box, Caddy, this stack), `test`

Log lines also have `source` (`docker`, `pm2`, `caddy`) and `level` (`debug`,
`info`, `warning`, `error`). pm2 lines have `stream` (`out` or `error`: stdout
or stderr; uvicorn writes its INFO lines to stderr, so use `level`, not
`stream`). Caddy lines have `host` and `status`.

Multi-line output is joined into one entry: a Python traceback, a faulthandler
dump, a Next.js error with its stack are each a single log line in Loki, and
the pm2 `YYYY-MM-DDTHH:MM:SS:` prefix is stripped (Loki has its own timestamp).

App metrics: cards-api and memory-api (the API, not the MCP/plugin servers)
expose `/metrics` (prometheus-fastapi-instrumentator): `http_requests_total`
and `http_request_duration_seconds_bucket` by `handler` (the route template, so
`/cards/{handle}`, never the raw path; unmatched paths are one `none` value),
`method` and `status` (`2xx`..`5xx`), plus `process_resident_memory_bytes`.
Caddy answers 404 for `/metrics` on the public hosts, but the containers also
publish 8001/8002 on the box's public IP, so close those ports. MCP and plugin
traffic is only visible in the Caddy access log (per path) and in the
container CPU/RAM series.

pm2 metrics (`pm2_process_memory_bytes`, `pm2_process_cpu_percent`,
`pm2_process_restarts_total`, `pm2_process_uptime_seconds`,
`pm2_process_online`, `pm2_up`) carry the same `project`/`env` labels.

Some LogQL to start from:

```
{project="cards-api", env="prod"}
{level="error", env="prod"}
{project="persona-api"} |= "Traceback"
sum by (host) (count_over_time({source="caddy", status=~"5.."}[5m]))
```

## Dashboards

Four, provisioned into the Grafana folder "Zynd" from `grafana/dashboards/*.json`:

| Dashboard | Use it to |
|---|---|
| **Box overview** | see RAM, CPU, disk and OOM kills, who is using the memory (containers and pm2 processes stacked), and every pm2 process and container with uptime and restarts |
| **Project** | pick `env` and `project`: health, memory, CPU, restarts, request rate, 5xx share, p95 latency per route, and that project's error and full logs |
| **Logs** | search every line by env, project, level and text; volume by level; crashes (tracebacks, fatal errors) |
| **Edge (Caddy)** | public traffic per hostname, 5xx, latency, top 404 paths, clients and user agents, uptime and certificate expiry |

`grafana/import/zynd-overview.json` is a fifth, one-screen dashboard that is *not* provisioned: import it
by hand (Dashboards -> New -> Import) and it is yours to edit and save in the UI.

They are generated: edit `grafana/build_dashboards.py`, run
`python3 infra/observability/grafana/build_dashboards.py`, commit the script and
the JSON. Grafana's UI edits can't be saved (provisioned), so a change made there
is lost on the next update. Every query was run against the live Prometheus/Loki
when written; the Traffic row of Project is empty for services that don't expose
`/metrics` (everything but cards-api and memory-api).

## Alerts

23 rules in `prometheus/alerts.yml`, evaluated by Prometheus. See them, and what is
firing, in Grafana (Alerting -> Alert rules, data source Prometheus) or at
`127.0.0.1:9090/alerts` over the tunnel. **Nothing is sent anywhere yet**: there is
no Alertmanager, so no Slack/Telegram/email. When a channel is chosen, add an
alertmanager container, an `alerting:` block in `prometheus.yml` and a receiver.

| Alert | Fires when | Severity |
|---|---|---|
| BoxMemoryLow / BoxMemoryCritical | available RAM < 15% for 5m / < 7% for 2m (no swap) | warning / critical |
| BoxOOMKill | the kernel killed a process | critical |
| BoxDiskFilling / BoxDiskCritical / BoxDiskFullIn24h | `/` < 20% free for 15m / < 10% for 5m / full within 24h at the 6h trend | warning / critical / warning |
| BoxCPUHigh | CPU > 90% for 15m | warning |
| PublicURLDown(Dev) | a probed public URL fails for 2m (prod) / 5m (dev) | critical / warning |
| Pm2Down | the pm2 daemon doesn't answer for 1m | critical |
| Pm2ProcessDown(Dev) | a pm2 process isn't online for 2m (prod) / 5m (dev) | critical / warning |
| Pm2RestartLoop, ContainerRestartLoop | 3+ restarts in 15m (a deploy is one) | warning |
| ContainerGoneProd / ContainerGoneDev | a container seen in the last 30m has disappeared (a redeploy's gap is ridden out) | critical / warning |
| High5xxRateProd / High5xxRateDev | over 5% of requests are 5xx for 5m (with real traffic) | critical / warning |
| HighLatencyP95 | p95 above 2s for 10m | warning |
| CertificateExpiresSoon / VerySoon | under 14 / 7 days left | warning / critical |
| ScrapeTargetDown | Prometheus can't scrape an exporter for 5m | warning |
| LogsBeingDropped | Alloy dropped over 50 entries in 15m | warning |

Tests: `prometheus/alerts_test.yml` (promtool, command at the top of the file) covers the
prod/dev severity split, a deploy gap not counting as "container gone", one restart not
being a loop, and the exclusion below. Run it after changing a rule.

**Temporary:** `ScrapeTargetDown` ignores prod `cards-api` and `memory-api`, because prod
doesn't serve `/metrics` until it runs the phase 3 build. After that deploy, delete the
second clause of that rule (and its test) so those targets are watched too.

## Logs API

An authenticated, bounded HTTP API over Loki (`infra/observability/logs-api/`), for scripts and other
tools that want the logs without Grafana. Loki itself stays on loopback: its API has no login, takes raw
LogQL with no limits and has delete endpoints. The service listens on `127.0.0.1:8200`, and Caddy serves
it at **https://169.58.17.193:4443** (self-signed certificate, so `curl -k`; the port must be allowed in
ufw by hand). Interactive reference with every parameter: `https://169.58.17.193:4443/docs`.

Auth: `Authorization: Bearer <key>`. The keys are `LOGS_API_KEYS` (comma-separated) in
`~/.zynd-obs/.env` on the box, generated by `apply.sh`. With no key configured the API refuses
everything (503) instead of running open. Caddy does not record the `Authorization` header in its access
log, so the key doesn't end up in Loki.

| Endpoint | Gives you |
|---|---|
| `GET /v1/sources?since=24h` | What is collected: the label values you can filter on, and per source/env/project the line count by level and the time of the latest entry |
| `GET /v1/logs` | The lines, newest first, filtered (below). Returns the LogQL it ran, `truncated`, and `next.end` to page back |
| `GET /v1/stats` | Line counts over time, `group_by=level` (or project, env, source, host, status, container, process), `step=5m` |

Filters (repeat a parameter or comma-separate values to match any of them): `source` (docker, pm2,
caddy), `env`, `project`, `level`, `container`, `process`, `stream`, `host` and `status` (Caddy; `404` or
`5xx`); `q` (contains, case-insensitive; repeat to require all), `not_q`, `regex`. Time: `since` (`30s`,
`15m`, `6h`, `2d`; default `1h`) or `start` / `end` (RFC 3339 or unix seconds), at most the 14 days kept.
`limit` is 1..5000 (default 100), `order` is `desc` or `asc`.

```bash
KEY=...    # from ~/.zynd-obs/.env
API=https://169.58.17.193:4443
curl -sk -H "Authorization: Bearer $KEY" "$API/v1/sources?since=6h"
curl -sk -H "Authorization: Bearer $KEY" "$API/v1/logs?project=cards-api&env=prod&level=error,warning&since=2h&q=timeout&limit=50"
curl -sk -H "Authorization: Bearer $KEY" "$API/v1/logs?source=caddy&status=5xx&start=2026-10-28T09:00:00Z&end=2026-10-28T10:00:00Z"
curl -sk -H "Authorization: Bearer $KEY" "$API/v1/stats?level=error&since=24h&group_by=project&step=1h"
```

Values are validated (letters, digits and `_.:/- ` only) and text filters are escaped, so a request
cannot inject LogQL. Tests (Loki mocked): `cd infra/observability/logs-api && pytest -q`.

## Deploy / update

On the box, as `ubuntu`, from any checkout that has this directory:

```
infra/observability/apply.sh
```

It copies the directory to `~/.zynd-obs` (bind-mounting the git checkout would
break whenever a deploy swaps files), starts or updates the stack, and reloads
what changed. It never touches the app containers or pm2, and the stack is its
own compose project (`zynd-obs`), so app deploys don't affect it.

The one env var is `GRAFANA_ADMIN_PASSWORD`, a secret kept only in
`~/.zynd-obs/.env`.

## Things that will bite

- **cAdvisor must be >= 0.55.** Docker 29 uses the containerd image store, and
  older cAdvisor then sees only the root cgroup (no per-container series).
- **Host networking is deliberate.** Apps listen on `127.0.0.1`, which a
  bridge-network container can't reach. If you add a service, give it
  `network_mode: host` and bind it to `127.0.0.1` on a free port.
- **Caddy metrics are per server, not per host** (Caddy 2.6). Per-host
  traffic and 5xx rates come from the access log in Loki.
- **Renaming a `loki.source.*` component in `alloy/config.alloy` resets its
  read position**, so Alloy re-reads every pm2 log file from the start and
  re-ingests the whole history stamped "now". Keep component names stable; if
  it happens, delete the duplicates with
  `POST :3100/loki/api/v1/delete?query={source="pm2"}&start=..&end=..` (end can't
  be in the future; Loki applies deletes after 24h).
- **Alloy `stage.match` selectors need LogQL double-quoted strings.** Backtick
  strings are rejected at runtime (and `alloy validate` doesn't catch it), so
  regexes need four backslashes, and non-ASCII symbols are written as `\\x{26A0}`.
  Test a pipeline change with a throwaway Alloy before applying it.
- **The pm2 exporter only calls `pm2 jlist` when the daemon's pid is alive**,
  because the CLI would otherwise start a new daemon. When pm2 is down it
  reports `pm2_up 0`.
- **Loki 3.5 logs `negative structured metadata bytes received` at error level on every
  push** (harmless). Alloy drops those lines so they don't drown the error counts.
- **The first start reads the existing pm2 logs from the beginning**, so
  counts over the first day include history.
