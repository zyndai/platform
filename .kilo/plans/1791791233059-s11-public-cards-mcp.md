# S11 — Public Cards MCP (implementation plan)

## Status today

**Not implemented.** No `FEATURE_S11_PUBLIC_MCP`, no `/cards-public-mcp`, no public tools `search_people` / `get_card` / `ask_card` / `request_intro`, no `zynd://card/{handle}` resource, no `find-people` prompt.

Reusable building blocks (do not reimplement):

| Piece | Where |
|---|---|
| Search + S03 claimed default | `services/cards-api/api/ask.py`, `api/agents.py`, `services/search.py` |
| CardView (S06) | `GET /cards/by-handle/{handle}/view` → `services/card_view.py` |
| Card Q&A | `POST /v1/chat/{handle}` (SSE) in `api/chat.py` |
| `agent_fetch` events | `services/cards-api/services/events.py` (already on `/ask`) |
| Auth’d personal MCP | `services/memory/app/mcp_http.py` at `api.zynd.ai/mcp` |
| Agent discovery pages | `apps/cards-web` `/for-ai`, `llms.txt`, `agents.txt` (REST only today) |

Do not confuse with: memory `find_people` (auth’d), persona `search_people` / QuickEnrich, or cards-api `/cards/mcp/*` (owner fact-review REST).

---

## Locked decisions

1. **Host:** all MCP stays in `services/memory` (ops/architecture preference).
2. **Shape:** same `mcp` container / process, **second FastMCP app with no auth** mounted at `/cards-public-mcp`. Personal `/mcp` keeps `RemoteAuthProvider` unchanged. Putting unauthed tools on the existing FastMCP instance is rejected — transport auth is server-wide (`ZyndTokenVerifier` rejects empty bearers).
3. **Backend:** thin HTTP client to cards-api (no duplicated search/view logic).
4. **`ask_card`:** wrap existing chat. Actual path is **`POST /v1/chat/{handle}`** (not `/cards/{handle}/chat`). Drain SSE into a single assistant answer string; label `role: assistant` / S14-style disclaimer in the tool description.
5. **Defaults:** honour S03 — claimed only unless `include_unclaimed=true`; unclaimed results must not include contact fields.
6. **Rollout:** `FEATURE_S11_PUBLIC_MCP` (memory settings); Caddy route; start unlisted, advertise on `/for-ai` + `llms.txt` after metrics week.

---

## Target architecture

```
MCP client (no creds)
    → api.zynd.ai/cards-public-mcp*   (Caddy)
    → mcp:8090  Starlette root
         ├─ /mcp*              → existing FastMCP("zynd", auth=…)
         └─ /cards-public-mcp* → FastMCP("zynd-cards-public", auth=None)
                tools → HTTP → cards:8000
                  GET  /ask?q=&limit=&include_unclaimed=
                  GET  /cards/by-handle/{handle}/view
                  POST /v1/chat/{handle}  (SSE → text)
```

Internal base URL: `http://cards:8000` in compose; configurable via e.g. `CARDS_API_BASE_URL`.

## Implementation tasks

### PR1 — Server skeleton + search + get_card + tests

1. **Config** (`services/memory/app/config.py`):
   - `feature_s11_public_mcp: bool = False`
   - `cards_api_base_url: str` (default `http://cards:8000` in prod compose; localhost for tests)
   - Optional: rate-limit knobs (IP/UA token bucket), response size cap, `get_card` TTL seconds

2. **New module** `services/memory/app/cards_public_mcp.py`:
   - `FastMCP("zynd-cards-public", instructions=…)` — **no** `RemoteAuthProvider`
   - HTTP helper (httpx) with timeouts + size caps
   - Tools:
     - `search_people(query, filters?, k, include_unclaimed=False)` → call `/ask` (or `/v1/agents/search` if filters needed); map to envelope: ranked cards with `match_reasons`, `claimed`, `fresh_as_of` (when present), `url` / `cite_as`
     - `get_card(handle)` → `GET /cards/by-handle/{handle}/view`; strip contact if ever unclaimed; Cache-Control / in-process TTL cache
   - When flag off: tools return a clear “not enabled” error (or app not mounted)

3. **Compose ASGI** in `mcp_http.py` (or small `mcp_asgi.py`):
   - Build Starlette/FastAPI parent that mounts:
     - existing `mcp.http_app(...)` at `/` (preserve current `/mcp` behaviour clients already use — verify path prefix FastMCP expects today)
     - public app at `/cards-public-mcp` when flag on
   - Keep `uvicorn app.mcp_http:app` entrypoint
   - `allowed_hosts` for both; public app must not advertise OAuth discovery

4. **Tests** `services/memory/tests/test_cards_public_mcp.py`:
   - Mock cards-api HTTP
   - Claimed-only default; `include_unclaimed=true` → `claimed:false`, no contact
   - Golden prompt shapes for tool descriptions (“when to use”)
   - Flag off behaviour

### PR2 — ask_card + resources + prompt + request_intro stub

1. `ask_card(handle, question)`:
   - `POST /v1/chat/{handle}` with `{"messages":[{"role":"user","content": question}]}`
   - Consume SSE (`data: {"response": "..."}` chunks until `[DONE]`); return `{answer, handle, labelled: "assistant", cite_as}`
   - Map 403 unclaimed / 429 / 503 to clear tool errors

2. MCP resource `zynd://card/{handle}` → same payload as `get_card`

3. MCP prompt `find-people` → guides client to call `search_people` then `get_card` / `ask_card`

4. `request_intro(...)` → stub `{"enabled": false, "message": "not enabled"}` (S12)

### PR3 — Rate limits, caching, observability, docs surface

1. Token-bucket per IP + UA on public MCP requests (middleware or tool wrapper); 429 with clear MCP error text
2. In-process TTL cache for `get_card` / resource
3. Emit / proxy `agent_fetch` with `meta.tool` = tool name + coarse query category (prefer calling cards-api so S04 attribution stays owner-visible; do **not** store full query text until privacy review)
4. Docs page section + “Add to your AI” on `apps/cards-web` `/for-ai`; add MCP URL to `llms.txt` / `agents.txt` (behind same flag or after unlisted week)
5. Optional `/.well-known` MCP listing only when ready to go public

### PR4 — Infra + discovery listing

1. `infra/api-box/Caddyfile` (and `infra/single-box/Caddyfile` if present):

   ```
   handle /cards-public-mcp* {
     reverse_proxy mcp:8090
   }
   ```

   Place **above** the catch-all; do not break `/mcp*` or OAuth `/.well-known/oauth-protected-resource*`.

2. Compose: ensure `mcp` can reach `cards` on the shared network; set `CARDS_API_BASE_URL=http://cards:8000` and `FEATURE_S11_PUBLIC_MCP` in memory `.env.prod` when enabling

3. Health: public MCP ping / tools/list when flag on

4. Rollback: unset flag **and/or** remove Caddy handle

## Acceptance criteria (map to work)

- [ ] MCP client with **no credentials** can `search_people("AI compliance founders")` and get **claimed-only** cards with `match_reasons`, `fresh_as_of` (when S06 on), `cite_as` / url
- [ ] Unclaimed absent unless `include_unclaimed=true`; then `claimed:false` and **no contact**
- [ ] Rate limit → clear error; latency baseline then p95 target
- [ ] Golden-prompt / tool-description review passes
- [ ] `request_intro` stub only
- [ ] Personal `/mcp` OAuth behaviour unchanged

## Risks / out of scope

- Abuse/scraping → rate limits, no bulk export tool
- Query-log privacy → coarse category only until review
- Search quality → owned by S06/search, not re-tuned here
- Intro action → S12
- Do **not** weaken `ZyndTokenVerifier` / anonymous tokens on personal MCP
- Prod Caddy / DNS / env flag flip → ask a human (AGENTS.md §6)
