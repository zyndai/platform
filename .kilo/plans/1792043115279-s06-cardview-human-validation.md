# S06 CardView: human validation

## Purpose and state

S06 makes a claimed person's approved public memory facts discoverable and consistent across profile, agent-readable JSON, structured metadata, search and profile chat. A fact carries its text, type, source, approval time, optional expiry and confidence; `cite_as` is the canonical profile URL. Private or revoked facts should not be exposed. `is_seeking`, `is_working_on` and `is_building` expire after 7, 14 and 60 days respectively according to the current Cards builder (measured from approval). The backend implementation is present in this checkout; that does not establish that it is deployed at cards.zynd.ai/api.zynd.ai. No production changes, backfill, or approval mutations are authorized by this validation plan.

## Preconditions

1. Choose a **claimed, published** test card with a known handle and owner access. Prefer a deliberately distinctive approved fact, such as `LinkedIn outreach infrastructure SendPilot`, that is not already in its headline, summary or skills. Obtain the owner's consent before making it public. Have one private/unapproved control fact and, if available, a revoked or expired control fact. Avoid real private information.
2. Confirm both Cards API and Cards web deploy versions and S06 flags. Cards API `FEATURE_S06_CARDVIEW` defaults true, but gates only typed search reasons/freshness boost; the API `/view`, embedding and chat fact path remain on. Web `NEXT_PUBLIC_FEATURE_S06_CARDVIEW` defaults false in `.env.local.example`; verify its deployed value before claiming that web uses `/view`. Verify the Cards site/API are actually running this checkout's release, because the repo README describes a separate live checkout.
3. Owner may use `/p/{handle}/edit` to review/approve public memory and its memory import workflow; approval then calls the owner-only refresh. Otherwise wait for the Cards memory refresh job. Do not ask a human to edit production SQL, run the backfill or set production flags as part of this read-only check.

## Manual checks

1. Open `https://api.zynd.ai/cards/by-handle/{handle}/view` and inspect `claimed: true`, `identity`, `facts`, `cite_as` and `fresh_as_of`. The approved unique fact should appear exactly once with `type`, `source`, `approved_at`, `expires_at` where applicable and `confidence`. The private/revoked control must be absent. If `/view` returns 404 or lacks the expected fact, confirm publish/claim status, deployment, owner approval and refresh before interpreting later failures.
2. Open `https://cards.zynd.ai/p/{handle}` anonymously. Find the **MEMORY** tile; expand **See all** if necessary. The same live fact text should appear. Open `/p/{handle}/data.json` and compare `zynd:facts` text to `/view` and tile, allowing UI grouping/deduplication and JSON's additional metadata. Inspect `zynd:cite_as`, `source`, `approved_at`, `expires_at`, `knowsAbout`, and non-empty `jobTitle`/`worksFor` when relevant. Empty `zynd:facts`, credentials and organizations should be omitted instead of `{}` placeholders. View page source and search for `application/ld+json` to inspect Person `knowsAbout`, `jobTitle`, `worksFor`; do not assume every fact type maps to each Schema.org field.
3. Search `https://cards.zynd.ai/find?q=linkedin%20outreach` and `https://api.zynd.ai/ask?q=linkedin%20outreach` (substitute your unique terms). The test card should be present, preferably high-ranked, with a `match_reasons` item `{ "type": "memory", "text": "..." }` on the API; UI renders this as `Memory: ...`. A successful `/view` alone does not prove search: older embeddings may need the off-peak backfill. Search quality and rank can vary with other cards.
4. On `/p/{handle}`, ask the profile chat a question answerable only by the approved fact, e.g. "What is this person building for LinkedIn outreach?" It should answer using that fact without claiming to be the person. Ask about the private control; it should not disclose it. Chat is generative, so compare meaning against `/view`, not exact sentence. Chat availability also depends on its model service.
5. Inspect `https://cards.zynd.ai/llms.txt` for the person's `cite_as` URL, and `/llms-full.txt` for `Cite as` and an approved-facts summary if the web flag is on. The short `llms.txt` is a directory of links, not a per-fact dump. Check an unclaimed card as a negative control: `/data.json` should return 410, `/view` 404 and `/ask` should omit it by default.
6. For expiry, use a prepared test fixture/environment with an already-expired `is_seeking` fact (approved >7 days ago), or wait for its natural expiry. Without changing production data, confirm it disappears from `/view`, the tile, JSON, chat answers, and memory match reasons. A stored vector may still retrieve a card as a candidate, so an expired phrase in other card fields prevents this from being a clean negative search test. JSON/page can cache for about 60 seconds; re-check after caches clear. Do not use wall-clock tricks or synthetic prod DB writes.

## Operator-only verification and caveats

- If search misses a newly synced fact even though `/view` has it, confirm embedding refresh/backfill status. `services/cards-api/scripts/reembed_all.py` offers a dry run and `--apply --after-handle` resume; `--apply` writes embeddings and incurs model cost, so obtain the required operational approval and run off-peak. Capture processed/failed counts and retry failures before declaring completion.
- Compare facts at a single approximate moment. Memory refresh is snapshot-based, and page/data caching plus asynchronous embedding refresh can temporarily produce different states.
- Current code does not exclusively derive every surface from one serialized object: the web page and JSON retain full-card fallbacks, `llms.txt` uses full-card summary text, and JSON-LD differs from `data.json` in mapping. `FEATURE_S06_CARDVIEW=false` is not a complete rollback: search still consumes memory text, `/view` still exists, and chat still reads CardView. Treat a strict all-surface parity claim as a follow-up implementation requirement, not an automatically satisfied result of these checks.
